> En kathara 9bind/bind viene por defecto en la imagen base, en el anterior TP al instalar quagga + zebra y hacer los ruteos dinámicos, todos los dispositivos de la topología corrian con quagga. Entonces hay que indicar en el `lab.conf` que el host C corra con kathara base

> Después para comenzar a configurar un servidor DNS, bind lee por defecto un archivo llamado `named.conf` indicando las configuraciones y las zonas del servidor
``` text
options
{
    directory "/var/cache/bind";

    listen-on { 11.11.0.1; };

    allow-query { any; };

    recursion yes;

    allow-recursion { any; };

    forwarders { 8.8.8.8; };

    forward only;

};

zone "ramos.izo"
{
    type master;
    
    file "/etc/bind/db.ramos.izo";

};
```
> Lo creamos en la carpeta `shared/` y en `hc.startup` lo copiamos a la carpeta `/etc/bind/` junto a la base de datos de la zona

- `directory`: directorio base de trabajo de BIND. <br>
- `listen-on`: IP por la que atiende consultas (la IP del Host C en la LAN C). <br>
- `allow-query`: quién puede hacer consultas (any = cualquiera).
- `recursion`: permite resolver nombres que no son de su zona (necesario para reenviar a Internet). <br>
- `allow-recursion yes | no`: a quién se le presta el servicio de recursión. <br>
- `forwarders`: servidor al que se le reenvían las consultas de dominios que no son de la zona. En este caso usamos el servidor DNS de anteriores TPs(8.8.8.8, DNS de Google). <br>
- `forward only`: usa solamente el forwarder, sin intentar resolver por su cuenta. <br>
- `zone "ramos.izo"`: declara la zona que administra este servidor. <br>
- `type master | slave`: este servidor es la autoridad de la zona (primario). <br>
- `file`: ruta del archivo con los registros de la zona.

b) Agregar al DNS todos los nombres de los dispositivos (subdominios) <br>
> Archivo de la base de datos de la zona con todos sus hosts `db.ramos.izo`
``` text
@   IN  SOA hc.ramos.izo. admin.ramos.izo. (
            2026100701  ; 1. Serial
            3600        ; 2. Refresh
            900         ; 3. Retry
            604800      ; 4. Expire
            60 )     ; 5. Negative cache TTL

@     IN  NS  hc.ramos.izo.

; Hosts
ha   IN  A    170.16.128.1
hb   IN  A    200.3.124.1
hc   IN  A    11.11.0.1
hd   IN  A    129.30.192.65

; RA
ra0  IN  A    170.16.255.252
ra1  IN  A    192.168.50.129
ra2  IN  A    192.168.50.142

; RB
rb0  IN  A    200.3.124.60
rb1  IN  A    192.168.50.130
rb2  IN  A    192.168.50.134
rb3  IN  A    192.168.50.145

; RC
rc0  IN  A    11.11.15.252
rc1  IN  A    192.168.50.141
rc2  IN  A    192.168.50.137
rc3  IN  A    192.168.50.149

; RD
rd0  IN  A    129.30.192.124
rd1  IN  A    192.168.50.150
rd2  IN  A    192.168.50.146

; RE
re0  IN  A    192.168.50.138
re1  IN  A    192.168.50.133
re2  IN  A    172.17.0.1
```
- `@`: atajo para el nombre de la zona (ramos.izo.). <br>
- `SOA (Start of Authority)`: registro obligatorio con los datos de la
- `zona`: <br>
    - `hc.ramos.izo.`: servidor primario. <br>
    - `admin.ramos.izo.`: correo del administrador (el primer punto reemplaza a la @).
    - `Serial`: número de versión; se debe subir cada vez que se edita el archivo.
    - `Refresh / Retry / Expire`: tiempos que usarían servidores secundarios. Son obligatorios por sintaxis aunque no haya secundarios.
    - `Negative cache TTL`: cuánto se recuerda que un nombre no existe.
- `NS`: indica qué servidor es el responsable de la zona. El nombre usado (hc.ramos.izo.) debe tener un registro A en la misma zona.
- `A`: asocia un nombre con una dirección IPv4 (equivale a una línea del viejo /etc/hosts).
> El punto final en hc.ramos.izo. indica nombre completo. Sin el punto, BIND le agregaría el dominio de nuevo.

• Ej: ha.apellido.izo, ra0.apellido.izo, ra1.apellido.izo
